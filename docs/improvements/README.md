# Improvement proposals

Proposals, completed investigations and implemented improvements. Each entry
records the problem, evidence, decision, and remaining limitations.

| Proposal | Status | Summary |
|---|---|---|
| [Indexing native memory](indexing-native-memory-plan.md) | Implemented | Design B: baseline WASM parser processes with bounded lifetimes, bounded malloc arenas and semantic-worker release under plans <=4 GiB. 2G passes (138.5 s), 7G median 4.507 GiB / 49.7 s. |
| [Indexing memory budget](index-memory-budget-plan.md) | Implemented | One frozen plan per full index/sync and a last-run budget hint. 7G median 4.460 GiB / 44.92 s; the 3G/2G failures are fixed by design B (indexing native memory). |
| [Manifest file search](manifest-file-search.md) | Deferred | `go.mod` and root `package.json` are excluded from the search corpus on purpose, and admission alone still ranks them 13 and 48. Needs an admission policy and a file/config ranking signal. |
| [Self-contained distribution](self-contained-distribution.md) | Deferred | Ship one self-contained executable per platform so a curl/PowerShell script, Homebrew, and npm become thin downloaders. |
| [Change-proportional edit sync](change-proportional-sync.md) | Deferred | Make a one-file edit sync cost scale with the change, not the repository: warm worker, watcher change sets, delta publication. |
| [Retrieval quality investigation](retrieval-quality-investigation.md) | Completed | Import-chunk noise, CBM retrieval ideas vs the LateOn reranker, and live search latency, measured on judged React queries. |
| [Repository vocabulary experiment](repository-vocabulary-experiment.md) | Indexing and search off by default | Publication-bound source vocabulary is retained as an opt-in experiment; the 46-query ablation regressed overall strict MRR@3 from 0.1486 to 0.0725. |
| [Implementation ownership in discovery](implementation-owner-ranking.md) | Definition discovery enabled by default | Published-symbol admission, definition/LateOn fusion and selection within each file improve measured top-rank discovery, with substantial latency and known regressions; the blanket path-preference pilot remains off. |
| [Agent alt terms in definition discovery](agent-alt-terms-definition-discovery.md) | Enabled by default when callers send `alt_terms` | Caller alt terms feed symbol-metadata search and definition fusion: 27 → 34 of 46 owners in the top 10; wrong terms cost more than none. Also records seven label corrections, a rejected window cap, and a Potion vs CodeRankEmbed comparison. |
| [Q5 retrieval and delegated validation owners](q5-retrieval-investigation.md) | Default repair implemented and evaluated | Broad Q5 now discloses both legality owners at ranks 4 and 8, with its guard at rank 1; admission alone was insufficient. |
| [Owner discovery and reranker investigation](reranker-owner-investigation.md) | Default repair retained after four-repository audit | Records ten-repository research, implementation, corrected ON/OFF symbol/path metrics, latency, regressions, causal limits and withdrawn recommendations. |
| [Release QA, October 2026](release-qa-2026-10.md) | In progress | Freshness, detect_changes and file_outline fixes from colonist-assistant QA, plus open defects from a staged-diff review and four QA workers. |
| [Incremental semantic analysis](incremental-semantic-analysis.md) | Deferred | Re-analyse only changed files on edit sync for CBM semantic languages, behind a provider-owned delta contract. |
| [MCP request latency findings](mcp-request-latency-findings.md) | Measured; lanes proposed, none implemented | NL search is about 2 s per call in steady state and not yet attributed to stages. Warm figures from `sync_in_progress` runs are not steady state. Status and architecture overview take 1.9–2.6 s. |
| [Voyage rerankers and definition fusion](voyage-reranker-and-definition-fusion.md) | Measured; fusion switch for the `rerank-3` family committed in `22a56c06` | On 28 questions Voyage `rerank-3` with definition fusion skipped reaches 20 owners at rank 1 and MRR 0.7798 against 13 and 0.5557 for the LateOn default. Fusion helps LateOn and hurts `rerank-3`. Figures came through a test hook, not the shipped Voyage path. |
| [Definition fusion: root cause and replayed rules](definition-fusion-root-cause.md) | Measured offline on 72 questions; no rule change recommended | The shipped name vote is worth as much as the reranker's whole verdict, so it lifts LateOn and overrides the Voyage models. Strict rank becomes the primary metric. The product already skips fusion for `rerank-3` and `rerank-3-lite`, which the data supports; no gentler rule gains more than one question in 72 for them. `rerank-3-lite` matches `rerank-3`. Of 25 owners absent from the rerank window, 18 are in no retrieval arm's top 80; classifying them is the next action. |
| [Reranker selection plan](reranker-selection-plan.md) | Tasks 1-8 committed in `46c0349b`; Task 9 (paid measurement) pending | Switch reranker from the CLI (LateOn, Voyage with any model name, none), pass model names through unchecked, and show the provider's error when a name is rejected. |
| [Owner recall and fusion: design checkpoint](owner-recall-design-checkpoint.md) | Checkpoint; not approved, not for implementation | Where the owner is lost on 72 questions (18 never retrieved, 7 lost to seats and fusion budget), why widening the rerank window does not help, why core fusion loses owners, the result of classifying the 18 (test files fill the retrieval arms), eight proposals with their deciding experiments, the variant sweep, and the test-row cap and caller alt terms through the real local reranker (alt terms: MRR 0.3559 to 0.4985; the cap does not move MRR). Ordering inside the window is the remaining gap. Written so a new session can resume. |
| [Owner ranking: handoff](owner-ranking-handoff.md) | Open investigation; entry point for a new agent | The whole story in order (LateOn, Voyage rerankers, definition fusion and the reranker-aware rule, owner recall, caller alt terms), the open problem (ordering inside the rerank window with the local reranker), the constraints on a solution, ideas and their state, a reading order for the other documents, a code map, and how to measure from a clean machine. |
| [Voyage embedding parity plan](voyage-embedding-parity-plan.md) | Plan only; awaiting review | Review findings on the Voyage embedder and reranker, a measured Voyage-embedding baseline on the 28 questions, and a six-phase plan (the last two are reranker failover to LateOn and indexing time): one Voyage client, a strict embedder, independent embedder and reranker selections in place of the offline/connected profile, and `satori embeddings use`. |
| [Release audit follow-up](release-audit-follow-up.md) | Plan; version bump needs a decision before publish | Open items after the release-audit fixes: minor bumps for core, mcp and cli (the range has breaking changes), keep the new `architecture_overview` `path`, measure `call_graph` source-reference cost before any paging redesign, and why the torn-receipt, stray `.tmp` and lock-window limits need no work now. |
